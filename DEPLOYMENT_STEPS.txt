STEP 05 — CREATE RENDER WEB SERVICE
--------------------------------------------------------------------------------
1. Go to https://dashboard.render.com
2. Click "New +" → "Web Service"
3. Connect your GitHub account if not already connected.
4. Select your nijotours repository.
5. Configure the service:

   Name            : nijotours-web
   Environment     : Java
   Region          : Choose closest to your users (e.g. Singapore for Japan travel)
   Branch          : main
   Root Directory  : (leave blank — project root)
   Build Command   : bash build.sh
   Start Command   : java -jar backend/target/travel-agency-1.0.0.jar
   Instance Type   : Free (or Starter for always-on)

6. Click "Create Web Service" (Render will start a build).

STEP 07 — BUILD COMMAND
--------------------------------------------------------------------------------
Build Command (already set in render.yaml):
  bash build.sh

What this does:
  1. Copies all frontend HTML/CSS/JS into backend/src/main/resources/static/
  2. Runs: mvn package -DskipTests -B
  3. Produces: backend/target/travel-agency-1.0.0.jar

Java version required: 17 (Render Java environment includes Java 17).
Maven required: Yes (Render Java environment includes Maven).


STEP 08 — START COMMAND
--------------------------------------------------------------------------------
Start Command (already set in render.yaml):
  java -jar backend/target/travel-agency-1.0.0.jar

The Spring Boot app will:
  - Listen on the port Render assigns ($PORT / 10000)
  - Connect to MySQL using the SPRING_DATASOURCE_* variables
  - Serve static files (HTML/CSS/JS bundled in the JAR)
  - Expose API at /api/**
  - Expose admin at /admin/**

STEP 12 — DNS RECORDS SETUP (at your domain registrar)
--------------------------------------------------------------------------------
Go to your domain registrar (GoDaddy, Namecheap, Cloudflare, etc.)
and add these DNS records:

For nijotours.com:
  Type   : A  (or ALIAS / ANAME if registrar supports it)
  Name   : @  (root domain)
  Value  : (IP address Render gives you — check Render dashboard)
  TTL    : 3600

  — OR —

  Type   : CNAME
  Name   : @
  Value  : nijotours-web.onrender.com
  Note   : Not all registrars allow CNAME on root. Use ALIAS/ANAME if available.
           If only A record is supported, use the IP from Render dashboard.

For www.nijotours.com:
  Type   : CNAME
  Name   : www
  Value  : nijotours-web.onrender.com
  TTL    : 3600

DNS propagation may take 5 minutes to 48 hours.
Check progress at: https://dnschecker.org


STEP 13 — SSL CHECK
--------------------------------------------------------------------------------
Render provides free SSL (Let's Encrypt) automatically.
After DNS propagation is complete:

1. Visit https://nijotours.com — browser should show padlock (secure).
2. Visit https://www.nijotours.com — same.
3. If you see "Not Secure" or certificate warning:
   - Wait 15–30 minutes after DNS propagates.
   - Check Render Dashboard → nijotours-web → Custom Domains → SSL status.
   - If status shows "Pending", wait more.
   - If "Error", try removing and re-adding the domain.

Mixed content warning fix:
  All API calls use relative URLs (e.g. /api/packages), so they always match
  the current protocol. No hardcoded http:// references remain in this project.

STEP 15 — DATABASE SETUP
--------------------------------------------------------------------------------
DATABASE DETECTED: MySQL

Render's FREE plan does NOT include MySQL hosting.
You need an external MySQL database.

RECOMMENDED: PlanetScale (free MySQL-compatible cloud database)
  1. Sign up at https://planetscale.com
  2. Create a database named: travel_agency
  3. Go to "Connect" → choose "Java / JDBC"
  4. Copy the connection string
  5. Set in Render environment:
       SPRING_DATASOURCE_URL      = (PlanetScale connection string)
       SPRING_DATASOURCE_USERNAME = (PlanetScale username)
       SPRING_DATASOURCE_PASSWORD = (PlanetScale password)

Important: Add ?useSSL=true&serverTimezone=UTC to the JDBC URL if not already present.

Tables are auto-created on first startup (JPA_DDL_AUTO=update).
Seed data (admin user, locations, packages) is inserted automatically
by DataInitializer.java when the tables are empty.

NOTE: PlanetScale uses a slightly different MySQL mode. If you see errors
about "foreign key constraints", add &sessionVariables=sql_mode=''" to the URL.


STEP 16 — FIX COMMON ERRORS
--------------------------------------------------------------------------------

BUILD FAILED:
  Problem : "mvn: command not found"
  Fix     : Make sure Render Environment is set to "Java" (not Node/Docker/etc.)
            Render's Java env includes Maven. Re-check service settings.

  Problem : "Could not copy frontend files"
  Fix     : Check build.sh is executable (Render usually handles this).
            Try adding: chmod +x build.sh at the start of the build command.

  Problem : "Compilation error in Java source"
  Fix     : Run locally: cd backend && mvn package -DskipTests
            Fix the compile error, commit, and push.

APP CRASHED / WON'T START:
  Problem : "HikariPool: Connection is not available"
  Fix     : Database is not reachable. Check SPRING_DATASOURCE_URL, USERNAME,
            PASSWORD in Render environment. Test the JDBC URL locally first.

  Problem : "Port already in use"
  Fix     : Render controls the PORT. Never hardcode port in start command.
            The app already reads from ${PORT:8080}.

MISSING ENV VARIABLES:
  Problem : "Could not resolve placeholder 'SPRING_DATASOURCE_PASSWORD'"
  Fix     : Add the missing variable in Render Dashboard → Environment.
            Save and trigger a new deploy.

CORS ERRORS (in browser console):
  Problem : "Access-Control-Allow-Origin" error when page loads API data
  Fix     : Check CORS_ALLOWED_ORIGINS in Render environment.
            Value must be exactly: https://nijotours.com,https://www.nijotours.com
            No trailing slash, no spaces between origins.

DATABASE CONNECTION ERRORS:
  Problem : "Communications link failure" or "Unknown host"
  Fix     : Check SPRING_DATASOURCE_URL is correct.
            Ping the host from your local machine.
            Make sure MySQL host allows remote connections (whitelist Render IPs
            or allow all: 0.0.0.0/0 — less secure but works for testing).

NOT SECURE / DANGEROUS SITE WARNING:
  Problem : Browser shows "Not Secure" after domain is connected
  Fix     : Wait for Render SSL to provision (up to 30 min after DNS propagates).
            Ensure DNS is pointing to Render (check with https://dnschecker.org).
            If still failing, remove domain in Render and re-add it.

  Problem : Mixed content warning (padlock with warning icon)
  Fix     : All API calls in this project use relative paths so this should not
            occur. If it does, open DevTools → Console and find the http:// URL.
            Replace it with https:// or a relative path.

ADMIN LOGIN NOT WORKING:
  Problem : Admin login fails with correct credentials
  Fix     : Check ADMIN_SEED_EMAIL and ADMIN_SEED_PASSWORD match what you set.
            These are only seeded when the users table is empty (first deploy).
            If you changed them after first deploy, reset via database directly
            or create a user programmatically.
